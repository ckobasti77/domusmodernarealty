- 2026-09-28 [03] **Search driver = ONE scope value per query.** `listings.scope` is derived as `bucket:transaction`, where bucket is `listed` (published + reserved), `closed` (sold + rented) or `hidden` (draft/review/withdrawn/archived, or a non-public visibility). - 2026-09-28 [03] Search strategy and its limits. Indexes: `by_scope_and_publishedAt`, `_price`, `_pricePerM2`, `_areaM2`, `by_scope_and_cityId_and_price`, `by_scope_and_municipalityId_and_price`, `by_scope_and_neighborhoodId_and_publishedAt`, plus `searchIndex("search_text")` filtered on scope/propertyType/cityId/hasTour. `lib/search.ts::pickDriver` picks the index: a price or area range WINS over the requested sort (a range must sit on the last indexed field); a single city or municipality plus a price range uses the compound index; otherwise the sort picks the index. When the chosen index cannot honour the sort, the bounded window is sorted in memory and the response is flagged `orderedInWindow: true`. Everything else (rooms, floor bands, heating, features, parking, construction, condition, furnishing, energy class, multi-select locations, tour/VAT/credit toggles) is post-filtered in JS by one `matches(doc, filters)` shared verbatim with the tests. Bounds: MAX_BATCHES 8 × BATCH_SIZE 100 (≤800 docs) per `listings.search`; COUNT_BATCHES 15 for `listings.count`, which returns `{count, exact}` so the UI can render "300+"; TEXT_TAKE 200 for text search (relevance only, single page — `withSearchIndex` cannot be ordered and scans ≤1024 docs); MAX_POINTS 1000 for `listings.mapPoints`. Location counts are denormalized in `locationCounts` and adjusted by `lib/counts.ts::applyCountDelta` inside the same mutation as every status/location write, never counted at read time. `publishedAfter` arrives as an absolute epoch from the client, so no query reads the wall clock.
