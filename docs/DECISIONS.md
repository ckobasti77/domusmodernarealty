- 2026-09-28 [03] Localized content is stored under the field key `sr` (not `sr-Latn`): Convex rejects object keys containing a hyphen, and module paths too. `LOCALE_FIELD` in `convex/lib/validators.ts` is the single mapping from the next-intl locale to the storage key, and `lib/derive.ts::pickLocale` is the only reader. The same rule forced `convex/seed/spec-types.ts` → `specTypes.ts` and `convex/seed/content/listings-1.ts` → `listings1.ts`.
- 2026-09-28 [03] **Search driver = ONE scope value per query.** `listings.scope` is derived as `bucket:transaction`, where bucket is `listed` (published + reserved), `closed` (sold + rented) or `hidden` (draft/review/withdrawn/archived, or a non-public visibility). Why: every public search, count and map query then needs exactly one index range, so the Convex pagination cursor stays a single cursor — merging cursors across several scopes would need a hand-rolled k-way merge. Consequence: `searchFiltersV.transaction` is REQUIRED (a property search is always either buy or rent, and the UI always has one selected), and sold/rented listings are reachable by URL and through `listings.similar` but do not appear in search results.
- 2026-09-28 [03] Search strategy and its limits. Indexes: `by_scope_and_publishedAt`, `_price`, `_pricePerM2`, `_areaM2`, `by_scope_and_cityId_and_price`, `by_scope_and_municipalityId_and_price`, `by_scope_and_neighborhoodId_and_publishedAt`, plus `searchIndex("search_text")` filtered on scope/propertyType/cityId/hasTour. `lib/search.ts::pickDriver` picks the index: a price or area range WINS over the requested sort (a range must sit on the last indexed field); a single city or municipality plus a price range uses the compound index; otherwise the sort picks the index. When the chosen index cannot honour the sort, the bounded window is sorted in memory and the response is flagged `orderedInWindow: true`. Everything else (rooms, floor bands, heating, features, parking, construction, condition, furnishing, energy class, multi-select locations, tour/VAT/credit toggles) is post-filtered in JS by one `matches(doc, filters)` shared verbatim with the tests. Bounds: MAX_BATCHES 8 × BATCH_SIZE 100 (≤800 docs) per `listings.search`; COUNT_BATCHES 15 for `listings.count`, which returns `{count, exact}` so the UI can render "300+"; TEXT_TAKE 200 for text search (relevance only, single page — `withSearchIndex` cannot be ordered and scans ≤1024 docs); MAX_POINTS 1000 for `listings.mapPoints`. Location counts are denormalized in `locationCounts` and adjusted by `lib/counts.ts::applyCountDelta` inside the same mutation as every status/location write, never counted at read time. `publishedAfter` arrives as an absolute epoch from the client, so no query reads the wall clock.
- 2026-09-28 [03] Location ids (`cityId`, `municipalityId`, `neighborhoodId`) live at the TOP level of `listings`, not inside `location`. Why: they are compound-index fields, and a top-level field keeps the index names inside the mandated `by_a_and_b` convention. `location` keeps only street/number/postcode/lat/lng/addressVisibility.
- 2026-09-28 [03] **Invite flow.** `convex/auth.ts::createOrUpdateUser` accepts a NEW account only when a pending, unrevoked, unexpired `invites` row exists for that email; it then copies role (and agentId) from the invite, stamps `acceptedAt`, links the agent profile and writes an activity row. The bootstrap (`seed:createAdmin`) writes its own invite first and then calls `createAccount`, so there is exactly one code path and no "first user is free" hole. Tokens: two `crypto.randomUUID()` values with the hyphens stripped, stored only as a base64url SHA-256 digest, 7-day expiry, single use; creating a new invite for an address revokes any open one. `invites.checkToken` lets the acceptance page validate the link before showing the form. `beforeSessionCreation` also refuses a disabled user, so deactivating someone takes effect on their next sign-in.
