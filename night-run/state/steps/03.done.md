## Decisions

All eleven are in `docs/DECISIONS.md`. The ones that change how later steps write
code:

1. **Localized content is stored under the key `sr`, not `sr-Latn`.** Convex
   rejects hyphens in object keys AND in module paths. Read localized values
   through `lib/derive.ts::pickLocale(value, locale)`; `LOCALE_FIELD` is the only
   locale→key map. The same rule forced `specTypes.ts` and `listings1.ts`.
2. **`searchFiltersV.transaction` is REQUIRED.** `scope` is
   `${bucket}:${transaction}`, so one query = one index range = one cursor. The
   search URL must always carry a transaction (default `sale`).
3. **Sold and rented listings are NOT in search results.** They resolve by slug
   (`listings.bySlug` accepts the `closed:` bucket) and appear in
   `listings.similar`, which is what PRD A5 needs for the Prodato/Izdato ribbon.
4. **Location ids are top-level on `listings`** (`cityId`, `municipalityId`,
   `neighborhoodId`); `location` holds only street/number/postcode/lat/lng/
   `addressVisibility`.
5. **`legal.encumbrance` IS public** — PRD A5 requires the teret in the legal
   block and PRD outranks ARCHITECTURE, which said to strip it.
6. **`previousPrice` is denormalized** on the listing; do not read
   `priceChanges` to render the "price reduced" badge.
7. **The convex-test harness lives in `tests/unit/convex-harness.ts`**, outside
   `convex/`, and must `registerComponent("rateLimiter", …)`.

**Accepted, not fixed (scale items, documented instead):**

- `listings.count` still walks up to 1 500 documents (`COUNT_BATCHES = 15`). Correct
  and bounded for this catalogue; at ~1 300 listings it needs a denormalized
  per-scope counter or `@convex-dev/aggregate`. It already reports `exact: false`
  so the UI can render "300+".
- `listingsAdmin.counts` (501/status), `analytics.dashboard` (501) and
  `analytics.agentResponse` (500 leads/agent) have the same shape of cap.
- `listings.search` can return more rows than `numItems` when a continuation batch
  overshoots (page size is a target, not a maximum, per the Convex guidelines);
  and when `orderedInWindow` is true the sort is per window, not global.
- `listings.slugsForSitemap` caps rentals at 500 and staples them onto page 1;
  step 09 should call it per transaction instead.
- Renaming a location does not rebuild the affected listings' `searchText`.
- `leadsAdmin.kanban`'s `total` is capped at `limit × 3`.

## Known issues

- **`listings.search` text mode is a single page of ≤200 results.**
  `withSearchIndex` cannot be ordered and scans ≤1024 docs, so a query with `q`
  returns `isDone: true` and no cursor. Step 06's Load-more must hide itself when
  `q` is set (or accept that text search is capped).
- **`listings.count` is approximate past 1500 documents.** It returns
  `{count, exact}`; render "300+" when `exact` is false. With the 30 demo
  listings it is always exact.
- **`listingsAdmin.counts` caps each status tab at 501.** There is no count
  operator in Convex; if a status ever exceeds 500 the tab needs the
  `@convex-dev/aggregate` component.
- **`stats.rollupDaily` has no rows yet** — the cron fires at 03:05 UTC, so
  `analytics.dashboard().series` is empty until it has run once. The KPI cards
  are computed live and do work.
- **Demo listings all carry `visibility: "public"`**, including the 2 reserved,
  1 sold and 1 rented. That is intentional (they must render with a ribbon), but
  it means `demo.counts` reports 103 rows across 9 tables, not 30.
- **`settings.isDemo` is `true`** because PIB is `000000000` and the registry
  number is `000`. `settingsAdmin.update` clears the flag automatically once real
  numbers are entered. The footer must show a "demo data" warning while it is set.
- **6 of the 30 demo listings share a cover photo with another listing.**
  `convex/seed/media.ts::buildPhotoPlan` assigns covers first, globally, so covers
  are distinct while the pool lasts — but 22 listings use `living` as their first
  category and the verified pool has only 16 living photos. 220 gallery slots are
  filled from 90 verified photos in total. Inventing image URLs is forbidden, so
  the fix is either more verified photos in `docs/assets/demo-media.json` or a
  different first category for some apartments.
- **`scripts/check-auth.mjs` reads `night-run/state/admin.json`.** It is a local
  dev tool only; never wire it into CI. Each run also creates one
  `invite-probe-<ts>@mihajlo-estate.local` editor account on the dev deployment to
  prove the invite-token gate, then disables it again — so the dev `users` table
  accumulates one disabled probe row per run.
- **Public form args gained three fields during the audit fixes.**
  `viewings.request` and `agents.slots` now need `tzOffsetMinutes`,
  `stats.trackFavorite` needs `sessionKey`, and `listingsAdmin.get`,
  `listings.previewBySlug` and `invites.checkToken` need `now`. Step 07/08 must
  pass them.
- No TODO comments were left in the codebase.

## Next steps should know

- **Verified against the installed packages, not from memory:** `createAccount`
  needs an `ActionCtx`, so `seed.ts` is a `"use node"` action and every seed write
  lives in `seedStages.ts`; `convexAuth`'s `createOrUpdateUser` IS called for the
  credentials provider when `createAccount` runs (hence the bootstrap invite);
  `Password({ profile })` must return an object that satisfies the whole `users`
  document, so it returns `role: "agent"` + `status: "active"` as the invite-less
  default, which `createOrUpdateUser` then overrides from the invite.
- **`crypto.subtle.digest` and `crypto.randomUUID()` both work inside a Convex
  mutation** — that is how `invites.hashToken` and the token generator work.
- **Query purity:** no query reads the wall clock. `listingsAdmin.todos`,
  `listingsAdmin.get`, `leadsAdmin.awaitingResponse`, `analytics.dashboard`,
  `analytics.{leadsBySource,agentResponse}`, `agents.slots` and
  `invites.checkToken` all take `now` (or `fromDay`) as an argument — the client
  must pass it. `scripts/audit-convex.mjs` fails the build-style check if a new
  query forgets.
- **`node scripts/audit-convex.mjs`** is a static self-audit of the whole function
  surface (139 functions): it fails on a missing `args`/`returns` validator, a
  `v.any()`, an admin function that reaches neither `requireRole` nor
  `loadEditable`, a public form mutation without `consumeLimit` +
  `assertHoneypotEmpty`, a `Date.now()` inside a query, or a `.collect()`. Run it
  after adding Convex functions in any later step.
- **Error shape:** every thrown error is a `ConvexError({ code, message, … })`
  with codes `UNAUTHENTICATED | FORBIDDEN | NOT_FOUND | INVALID_INPUT |
  PUBLISH_BLOCKED | RATE_LIMITED | SLOT_TAKEN | SPAM | CONFLICT`.
  `PUBLISH_BLOCKED` carries `reasons: string[]`; `RATE_LIMITED` carries
  `retryAfter` in ms. Step 07/08 map these to localized messages.
- **Public forms need three extra fields** from the client: `sessionKey` (8–64
  chars, from `hooks/useSessionKey.ts`), `hp` (the honeypot, must be empty) and
  `privacy: true`. `marketing` is separate and must default to unticked.
- **Rate limits** (token bucket per session + a fixed global window):
  leads 5/h burst 3, viewings 4/h burst 2, valuations 4/h burst 2,
  trackView 60/min burst 30; global 200 leads/h and 120 viewings/h.
- **`listings.bySlug` returns a tagged union** —
  `{kind:"listing"|"redirect"|"missing"}`. Step 07 must `notFound()` on
  `missing` and issue a 301 on `redirect`.
- **Images:** every DTO returns resolved `url` strings (storage ids are already
  converted through `ctx.storage.getUrl`). Demo photos are Unsplash URLs with
  `?w=1600&q=80&auto=format&fit=crop`; `next.config.ts` already allows the host.
- **Monogram avatars:** `toAgentPublic` always returns `monogram`, and `photoUrl`
  is absent for all four demo agents — render the monogram, never a stock face.
- **`testimonials.verified` returns 0 rows** by design; the Testimonials section
  must handle an empty list gracefully.
- **Page content** is `pages.get(key)` → `blocks: PageBlock[]`, a typed union
  (`richText | stats | steps | faq | cta | media | list`). The legal pages carry
  the "NACRT — proveriti sa pravnikom pre objave" warning in the first block, and
  their bodies contain `{{companyName}}`, `{{pib}}`, `{{mb}}`, `{{registryNo}}`,
  `{{address}}`, `{{email}}` placeholders the renderer must substitute from
  `settings.publicSettings`. The `cta` hrefs are canonical (`/valuation`,
  `/contact`) and must be routed through the next-intl `pathnames` map.
- **Content flagged by the translator agents, for step 04/05 to resolve:**
  `messages` uses lowercase "vaš" in `home.valuationHeading`/`valuationLede`
  while 04-CONTENT and the seeded page copy use capitalised „Vaš”; two different
  hero ledes exist (04-CONTENT vs `messages.home.heroLede`); the reply-time
  promise differs between 04-CONTENT, the final CTA and the seeded contact FAQ.
  Journal `tags` are a non-localized `string[]` and will render untranslated.
- **Re-seeding:** `npx convex run seed:all '{"force":true}'` wipes only `isDemo`
  rows, then rebuilds. `npx convex run listingsInternal:rebuildLocationCounts`
  repairs the denormalized counters if they ever drift.
