## Decisions

17 `[11]` entries in `docs/DECISIONS.md`. In brief:

- **Demo splat:** "Living Room and Kitchen" (ethan3111, CC BY 4.0) loaded on the first try; the fallback scenes were not needed. Spark 2.2 only decodes bundled SOG, so `meta.json` + WebPs are fetched and zipped in memory (`fflate`, stored).
- **Measured walk:** y-down scan, floor at y = 0, ≈ 1.73 units/m → eye height 2.75 units, speed scaled by `eyeHeight / 1.6`; polygon traced on a top-down density map; mesh turned 180° about X (Spark's convention); spawn/polygon/hotspots in that world frame.
- **Schema:** `walk3d.hotspots` and `tourScenes.credit` added.
- **Showcase = ME-1049**; ME-1044/1048 lost their copies of the same splat. Scene titles describe the actual panoramas.
- **three 0.185.1** so PSV and Spark share one copy.
- **Native `<dialog>`**, PSV created a tick after mount (Strict Mode).
- **Controls, tiering, FPS guard** as listed above; `lod: true` gives the guard a splat budget.
- **External tours:** one embed rule, server refuses other hosts, DTO exposes only `embedUrl`.
- **Validation on both save paths**, only new/changed blobs checked, replaced/deleted blobs released.
- **Design pass** (design-critic 5/10): brighter posters, unified panel stack, demo badge, shared room rail, legible overlays, themed PSV chrome, 2D link mode, phone tabs in one scrolling row.
- **Serbian says "360° tura"** everywhere ("obilazak" is a physical visit).
- **Admin tab** saves scenes explicitly ("Sačuvaj scenu"); walkthrough settings autosave with the listing.

## Known issues

- **Spark LoD build takes ~8.5 s** for the 3.85 M-splat demo (inside Spark's worker, behind the "Obrada modela…" state); first interactive frame ≈ 16–23 s on this machine incl. the 43 MB download. A smaller desktop SOG (or a pre-built LoD `.rad`) would cut it; the agency's own scans should be exported at ≤ 2–3 M splats.
- **No mobile model for the demo walk.** Light devices (iOS, ≤ 4 GB, Save-Data) see the size warning with "Ipak učitajte" + the 360° tour. Real phones were not tested (no device here); headless Chromium on this machine had the RTX 4060 via ANGLE, so the walk was verified with a real GPU, not SwiftShader.
- **The FPS guard was not triggered in testing** (the GPU never dropped below 30 fps). The logic is in `WalkEngine.guard`; it needs a check on an integrated-GPU laptop.
- **The camera can clip into low hanging objects** (the pendant lamp over the coffee table): collision is 2D (floor polygon), as planned; `collision.glb` with three-mesh-bvh is the documented next step.
- **Blob ownership** is still the step-09 6 h link window, not a ledger (convex-auditor L7, robust form). Clearing the walkthrough in the editor deletes its uploaded models on the next autosave without undo.
- **`listingsAdmin.get` returns no URL for an uploaded walk poster**, so after a reload the admin shows "Otpremljena slika" without a preview.
- **Editor header at 390 px**: status, "Sačuvano" and "Demo" collide (`EditorHeader.tsx`, step 08 file; reported by the admin agent, not changed here).
- **Landing e2e on the dev server:** 2 landing choreography tests failed once against `next dev` (cookie banner / rail pin timing); both pass on the production build (full run below).
- No TODO comments were left in the code.

## Next steps should know

- **Re-applying demo tours:** `npx convex run seedStages:applyDemoTours '{}'` (idempotent; demo listings only). `seed:all` writes the same data on a fresh deployment. Re-generating panoramas: `node scripts/fetch-demo-tours.mjs [--force]` (rewrites `convex/seed/tours.generated.ts`). The walk poster `public/media/tours/demo/living-room-kitchen-walk.jpg` is a frame captured from the viewer at the spawn point (a derivative of the CC BY scan; shown with its credit).
- **Coordinate frame for walk data:** world Y up; scans are assumed 3DGS/COLMAP y-down and turned 180° about X; `spawn.y` is the floor height; `eyeHeight` is in model units; yaw 0 looks toward −Z, positive yaw turns left.
- **Bundle check:** after `next build`, `node scripts/check-bundle-isolation.mjs` fails if any route's entry chunks contain PSV/three/Spark. Step 12's perf report can reuse its per-route gzip table.
- **CSP:** splat hosts and tour frame hosts live in `convex/lib/tours.ts` and are imported by `lib/csp.ts`; add a host there (e.g. the agency's R2 domain) and both the server rules and the CSP follow.
