### Metadata

- Every public route has `generateMetadata` with:
  - a localized title and description;
  - a self canonical;
  - hreflang for sr-Latn, en, ru, de and `x-default` (= the `/sr` URL);
  - Open Graph and a `summary_large_image` Twitter card. Pages without their own picture get the site share card.
- The home page has metadata now; before this step it had no canonical, hreflang or OG.
- Titles over 50 characters drop the " — Mihajlo Estate" suffix.
- Audit: `scripts/seo-audit.mjs` checks every sitemap URL plus favorites/compare in 4 locales:
  - status 200, `html lang`, title length (10–70), description length (50–230);
  - one `h1` in the server HTML;
  - self canonical, the hreflang set and reciprocity;
  - OG/Twitter tags, robots meta, JSON-LD, and that every `og:image` returns an image.
- The audit crawls as Bingbot, see DECISIONS [12].

### Sitemap and robots

- `app/sitemap.ts` lists static pages, listed listings, locations, posts and agents. Each URL has its 5 hreflang alternates, up to 5 images (XML-escaped) and a lastmod. It is backed by `convex/sitemap.ts` and regenerated hourly.
- `app/robots.ts` disallows `/admin`, `/api` and `/*/styleguide`, and points to the sitemap.
- The audit parses the XML with `saxes` (namespace-aware) and checks:
  - namespaces and absolute locs, with no duplicates;
  - every URL carries 5 alternates including itself, and every alternate is itself a loc;
  - lastmod format.
- Result: **valid**, with 336 URLs (326 KB), 164 lastmods and 196 URLs with images (644 images). Locations and agents have no last-modified field, so they carry no lastmod.

It also requires exactly one full agency node per page and no raw `</script`.

## Known issues

- **Mobile Lighthouse is 74 on search and listing** (target 75). The best runs reach 75 and 77, and `/sr` is 75. The concrete causes are in `docs/reports/perf.md`:
  - on localhost all JS runs before the first frame, and the simulate model counts it into LCP;
  - 130–165 KB gzip of app JS on every page (GSAP 49.5, Convex client 19.8, lucide 19) plus the framework; Lighthouse counts ~310 KB of script transfer on `/sr`;
  - 6 web fonts, 228 KB;
  - Next's polyfill module.

  Next candidates: mount the Convex provider only where live data is used, and inline the shell icons. Measure again on a hosted build (PSI + CrUX).
- **Lighthouse SEO on `/sr/nekretnine` intermittently reports "no meta description"** (3 of 6 runs). The description is in `<head>` on every crawl and Playwright load. The suspected cause is the ~680 KB document still hydrating; step 13 should check for hydration warnings there.
- **The `notFound()` 404 HTML** is still Next's `__next_error__` shell: no `lang` and no `h1` in the server HTML. The UI paints from the RSC payload on the client. Status 404, noindex and the localized title are correct.
  - The RSC payload carries `NEXT_HTTP_ERROR_FALLBACK;404` at the root, so the locale `not-found.tsx` boundary is not applied during SSR.
  - Not fixed in this step (it predates it; see step 10). Suspects: `experimental.globalNotFound` combined with a `[locale]` root layout.
- **All client message namespaces are still sent** (55 KB raw, ~12 KB gzip per page). See the [12] decision.
- **The search page document is large**: about 680 KB raw / 77 KB gzip, because each card's srcset and its RSC payload are duplicated.
- No TODO comments were left in the code.
